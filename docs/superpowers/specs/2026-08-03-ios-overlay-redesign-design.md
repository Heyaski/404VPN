# Overlay — переделка iOS-приложения под отказ Apple 4.3(a)

Дата: 2026-08-03. Статус: согласовано, готово к плану реализации.

## 1. Зачем

TestFlight App Review отклонил приложение по **Guideline 4.3(a) — Design: Spam**: «shares a similar binary, metadata, and/or concept as apps submitted to the App Store by other developers, with only minor differences».

Причина конкретна и относится к нам:

- **Бинарник.** WireGuardKit — та же открытая библиотека, что в сотнях приложений. Своего кода 846 строк, половина из них — сетевой слой, Keychain и тема. Приложение — два экрана: ввод кода и одна кнопка.
- **Концепция и UI.** Тёмный фон плюс большая круглая кнопка со свечением — самый копируемый VPN-интерфейс из существующих.
- **Имя.** «404VPN» попадает в паттерн `<слово>VPN`, под которым в сторе тысячи клонов.

Ответ в Resolution Center с тем же бинарником по 4.3(a) почти никогда не проходит. Нужны изменения в приложении.

**Что проверено и не мешает:** аккаунт зарегистрирован как организация, поэтому Guideline 5.4.1 (VPN только от организаций) выполняется. Других приложений под аккаунтом нет, значит сработал первый абзац письма — сходство с чужими шаблонами, а не с собственными приложениями.

**Отдельный риск, вне ревью:** Apple по требованию Роскомнадзора удаляла VPN-приложения из российской витрины. Принятое приложение может оказаться недоступно основной аудитории. Обходного пути на iOS нет; это риск бизнес-модели, а не предмет этой спецификации.

## 2. Решения

| Решение | Выбор |
|---|---|
| Имя в App Store | **Overlay**, разработчик — 404 Studio Tech |
| Bundle ID | без изменений, `co.404studio.vpn` |
| Имена таргетов и схем Xcode | без изменений (`VPN404`, `VPN404Tunnel`) — меняется только `CFBundleDisplayName` |
| Раскладка | вкладки, на первой — дашборд |
| Облик | приборная панель: плотная сетка карточек, моноширинные числа, тонкие рамки |
| Функции | автоподключение по правилам, kill switch, статистика и история сессий, виджет + Пункт управления + Shortcuts, фильтрующий DNS |
| Доставка статистики | оба канала: снапшоты в App Group плюс IPC для живого графика |
| Геопозиция | не запрашиваем |
| Счётчик заблокированного | из AdGuard Home по IP устройства, журнал запросов выключен |

Имя сервиса в боте, мини-приложении и на сайте остаётся прежним — переименовывается только приложение в App Store.

**Bundle ID не меняем осознанно:** приложение не опубликовано, имя в App Store Connect правится свободно, а новый bundle ID потянул бы новые App ID, App Group и профили без всякого влияния на 4.3.

**«Overlay» — распространённое слово,** имя может быть занято. Зарезервировать в App Store Connect до правки метаданных. Запасные варианты: «Overlay Net», «Overlay by 404».

## 3. Экраны

### 3.1 Соединение (дашборд)

Шапка с вордмарком и статусом. Широкая кнопка подключения. Карточка живого трафика с графиком — появляется только когда туннель поднят. Две мини-карточки: режим автоподключения и счётчик заблокированного. Карточка баланса с остатком дней и числом устройств.

Отвязка устройства переезжает отсюда в настройки.

### 3.2 Статистика

Переключатель периода: сутки, неделя, месяц. Столбчатый график по дням на Swift Charts (iOS 16+, отдельная зависимость не нужна). Итоги за период: скачано, отправлено, время под защитой. Список сессий: когда, сколько длилась, сколько трафика прошло.

Пока подключений не было — экран объясняет, что данные появятся после первого.

### 3.3 Настройки

- **Автоподключение** — главный переключатель, режим, список доверенных сетей.
- **Защита** — kill switch, DNS-фильтр со счётчиком.
- **Устройство** — имя, баланс, отвязка устройства.
- **О приложении** — версия, политика конфиденциальности, поддержка.

**Доверенные сети вводятся именем вручную.** Автоподстановка имени текущей Wi-Fi требует entitlement `com.apple.developer.networking.wifi-info` и разрешения на геопозицию. Для VPN-приложения запрос геопозиции — лишний повод для придирок в ревью и строка в декларации данных, которую придётся объяснять. Режимы «всегда», «только в сотовой сети», «только в Wi-Fi» работают вообще без разрешений; отсутствие запроса геопозиции становится пунктом описания в App Store.

## 4. Архитектура

### 4.1 Три процесса

Приложение, расширение туннеля и виджет — отдельные процессы iOS. Счётчики трафика знает только расширение, поэтому оно единственный источник правды.

Доставка идёт двумя каналами:

1. **Общий контейнер App Group** (`group.co.404studio.vpn`). Расширение раз в 5 секунд читает счётчики и пишет снапшот; оно же закрывает запись сессии при остановке. Читают приложение и виджет. Работает, когда приложение выгружено.
2. **IPC `sendProviderMessage`.** Пока открыт экран статистики, приложение раз в секунду запрашивает у расширения текущие счётчики и рисует живой график. Виджет в IPC не участвует.

### 4.2 Модули и границы

Общий код лежит в `Shared/` и компилируется во все три таргета.

**Новое:**

- `Shared/StatsStore.swift` — единственный, кто знает формат хранения. Снапшот и журнал сессий. Сессии хранятся **90 дней**, более старые отбрасываются при записи; этого хватает на самый длинный период в интерфейсе (месяц) с запасом.
- `Shared/TunnelStats.swift`, `Shared/SessionRecord.swift` — модели.
- `Shared/Preferences.swift` — настройки и последний известный баланс в общих `UserDefaults`.
- `Tunnel/RuntimeConfigParser.swift` — чистая функция: строка `getRuntimeConfiguration` на входе, счётчики на выходе.
- `App/Screens/` — `RootView` (TabView), `DashboardView`, `StatsView`, `SettingsView`, `RedeemView`.
- `App/Intents/` — `ConnectIntent`, `DisconnectIntent`, `ToggleIntent`.
- `Widgets/` — `StatusWidget` (экран блокировки), `ToggleControl` (`ControlWidget`, iOS 18+).

**Меняется:**

- `VPNManager` — правила автоподключения, kill switch, запрос счётчиков по IPC. Остаётся единственным, кто трогает NetworkExtension; экраны про `NETunnelProviderManager` не знают.
- `PacketTunnelProvider` — таймер снапшотов, обработка входящих сообщений.
- `AppState` — худеет до аккаунта и токена.
- `HomeView` → `DashboardView`.
- `Api` — в ответе туннеля появляется `dnsFiltered`.
- `project.yml` / `project.ui.yml` — таргет виджетов, папка `Shared`, `CFBundleDisplayName: Overlay`.

Имена таргетов и схем (`VPN404`, `VPN404Tunnel`) остаются прежними: они не видны пользователю, а переименование потянуло бы правку инструкций в `docs/DEPLOY.md` без всякой пользы для ревью.

Границы держатся на трёх решениях: парсер счётчиков — чистая функция и тестируется без сети; формат хранения знает только `StatsStore`, поэтому его можно менять, не трогая три процесса; NetworkExtension инкапсулирован в `VPNManager`.

### 4.3 Потоки

1. **Активация:** `RedeemView` → `Api.redeem` → Keychain → `AppState`.
2. **Подключение:** `DashboardView` → `VPNManager.install(config:)` → `NETunnelProviderManager`. Правила автоподключения и kill switch кладутся в тот же профиль.
3. **Во время работы:** расширение → `RuntimeConfigParser` → `StatsStore.writeSnapshot()`; при остановке — закрытие сессии.
4. **Живой график:** `StatsView` открыт → `VPNManager.requestStats()` → `sendProviderMessage` → ответ расширения.
5. **Виджет:** таймлайн WidgetKit → `StatsStore.readSnapshot()` плюс баланс, который приложение кладёт туда после каждого `/api/device/me`.
6. **Настройки:** `SettingsView` → `Preferences` → `VPNManager` перестраивает профиль.

## 5. Серверная часть

**AdGuard Home** в Docker на NL-сервере, подключается к сети, где уже живёт wg-easy. Многодомным становится AdGuard; **wg-easy не трогаем** — правило, записанное в `docs/DEPLOY.md` после инцидента с пропавшим у клиентов интернетом.

Адрес AdGuard на этой сети задаётся **статически**: после перезапуска динамический адрес уедет и фильтр отвалится.

**Резолвер не публикуется наружу.** Открытый DNS в интернете находят за сутки и используют для усиления DDoS. Порт 53 остаётся внутри docker-сети, никаких `ports:` на хост.

**Журнал запросов в AdGuard Home выключен.** Хранятся только счётчики по клиентам. Для VPN-сервиса хранение истории DNS-запросов — ровно то, чего обещают не делать; обещание «храним счётчики, не храним запросы» фиксируется в политике конфиденциальности.

Счётчик заблокированного берётся по IP устройства: у каждого клиента свой адрес в подсети WireGuard, AdGuard считает статистику по клиентам, бэкенд знает, какой адрес чей.

Адреса резолверов — настройки в админке (`dns_default`, `dns_filtered`), не константы в коде.

## 6. Изменения API

`POST /api/device/tunnel` — в ответе появляется `dnsFiltered: string[]` рядом с существующим `dns`. Оба набора приходят сразу, переключение фильтра происходит локально без похода на сервер.

wg-quick текст собирается на устройстве из структурированного ответа (`Api.swift`, `wgQuickConfig`), поэтому изменение сводится к одному полю в JSON и одной строке в сборке конфига.

`GET /api/device/dns-stats` — новый эндпоинт, возвращает `{ blocked: number, since: string }` для устройства, делающего запрос. Бэкенд сопоставляет устройство с его адресом в подсети WireGuard и берёт счётчик из AdGuard Home. Если AdGuard недоступен — `503`, приложение просто не показывает число.

Новых таблиц не нужно: статистика трафика целиком на устройстве.

## 7. Краевые случаи

**Автоподключение против нулевого баланса — главный риск.** Правила `NEOnDemandRule` заставляют систему держать туннель поднятым и блокируют трафик приложений, пока он не поднялся. Это и есть kill switch на iOS. Но при исчерпанном балансе сервер выключает пир, туннель не поднимется никогда, и человек остаётся **вообще без интернета**, не понимая причины.

Решение: при статусе `suspended` приложение снимает правила автоподключения, показывает объяснение на дашборде и возвращает правила после пополнения.

**Kill switch и `includeAllNetworks`.** Флаг гонит через туннель даже трафик, который обычно идёт мимо, из-за чего ломаются AirPlay, печать и устройства в локальной сети. Выключен по умолчанию; в интерфейсе — честная строка о последствиях, а не голый переключатель.

**Переключение DNS роняет туннель.** Адреса DNS зашиты в конфигурацию WireGuard, поэтому смена фильтра — это переподключение на пару секунд. Скрыть нельзя, только предупредить в интерфейсе.

**AdGuard недоступен или `dnsFiltered` пуст.** Фильтр в настройках недоступен с объяснением, туннель поднимается на обычном DNS. Фильтр никогда не должен мешать подключению.

**Нет сети.** Показываем последний снапшот из контейнера, а не ошибку поверх всего.

**Устаревший снапшот в виджете.** Данные подписываются временем.

**Отвязка устройства.** Правила автоподключения снимаются вместе с профилем, иначе система продолжит поднимать туннель.

**Недействительный токен.** Любой 401 возвращает на экран активации — уже реализовано в `AppState.handle(_:)`.

**Пункт управления на iOS 18.** Если система не даст стартовать туннель из процесса интента, откатываемся на вариант «элемент открывает приложение». Проверяется только на устройстве.

## 8. Тестирование

**Юнит-тесты** (всё, что чистое):

- `RuntimeConfigParser` — разбор счётчиков, включая мусор и обрезанный ввод.
- `StatsStore` — запись, чтение, агрегация сессий по дням, ротация старых записей.
- Сборка правил `NEOnDemandRule` по выбранному режиму — чистая функция, возвращающая массив правил.
- Сборка wg-quick с обоими наборами DNS.

**Бэкенд:** `dnsFiltered` в ответе туннеля; счётчик заблокированного через фейковый клиент AdGuard по образцу `FakeWgProvider`.

Существующие 11 iOS-тестов и 172 бэкенд-теста остаются зелёными.

**Руками на устройстве** (симулятор не умеет): автоподключение при переходе в чужой Wi-Fi, kill switch, виджет, Siri, Пункт управления.

## 9. Метаданные App Store

- **Имя:** Overlay. **Разработчик:** 404 Studio Tech. Подзаголовок — про соединение по коду.
- **Описание:** конкретные функции. Без «fast secure unlimited free vpn proxy».
- **Скриншоты:** шесть-восемь, показывают статистику, правила автоподключения, DNS-фильтр, виджет и Siri — не одну кнопку.
- **Политика конфиденциальности:** геопозицию не запрашиваем, журнал DNS-запросов не храним, храним счётчики.
- **App Review Information:** рабочий код доступа с балансом. Без него ревьюер упирается в экран активации и отклоняет заявку за невозможность проверить приложение — отдельная типичная причина отказа, не связанная с 4.3.
- **Resolution Center:** перечислить изменения и указать, что это клиент собственного сервиса, а не купленный шаблон.

## 10. Осознанно не делаем

- **Выбор локации** — сервер один, экран получился бы из одной строки; для ревьюера это скорее минус. Вернуть, когда появится второй сервер.
- **Подсчёт заблокированного на устройстве** — пакеты держит WireGuardKit, влезть в них можно только патчем вендорной библиотеки.
- **Смена bundle ID** — работы много, на 4.3 не влияет.
- **Запрос геопозиции ради автоподстановки имени Wi-Fi** — цена выше пользы.

## 11. Порядок работ

Объём большой, поэтому реализация идёт этапами, каждый из которых доводится до зелёных тестов и собираемого приложения:

1. **Фундамент** — `Shared/` (модели, `StatsStore`, `Preferences`), `RuntimeConfigParser`, снапшоты из расширения. Юнит-тесты. Видимых изменений нет.
2. **Экраны** — `RootView` с вкладками, `DashboardView` вместо `HomeView`, `StatsView` с графиком и историей. Приложение приобретает новый облик.
3. **Правила и защита** — автоподключение, kill switch, снятие правил при `suspended`, `SettingsView`.
4. **Сервер** — AdGuard Home, `dnsFiltered` в ответе туннеля, `GET /api/device/dns-stats`, настройки в админке; затем переключатель фильтра в приложении.
5. **Расширения системы** — App Intents, виджет экрана блокировки, `ControlWidget`.
6. **Метаданные и подача** — имя, описание, скриншоты, политика конфиденциальности, демо-код в App Review Information, письмо в Resolution Center.

Этапы 1–3 не зависят от сервера, поэтому могут идти параллельно подготовке AdGuard.
